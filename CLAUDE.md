# In This Town (repo: this-town)

Hackathon project. Renamed from Questline (D15): players see "In This Town"; code identifiers (`@questline/*`, the `questline` database, `questline.page`) keep the old name. MBTA riders turn on Ride Mode and get matched with the closest rider on their train who shares their interests. Each train car has a kiosk (Pi + screen + LEDs + NFC tag). Meta Ray-Ban Display glasses show who your match is and where to go. The kiosk runs a short mission and hands out stamps.

## Read first

- `docs/architecture.md`: how everything fits. Source of truth.
- `docs/decisions.md`: what changed from the v1 spec and why. The v1 spec in `docs/archive/` is out of date (no badges, no camera lock-on, no mutual consent, no BLE).
- `packages/protocol/src/`: every REST body and WebSocket event.

## Layout

- `apps/worker`: Cloudflare Worker (Hono, D1, `TrainRoom` Durable Object). Serves all three web apps from `public/`.
- `apps/phone-web`: rider phone web app (React + Vite, base `/`)
- `apps/glasses-web`: Meta Ray-Ban Display Web App (React + Vite, base `/g/`, 600x600, black background)
- `apps/kiosk-web`: kiosk screen (React + Vite, base `/kiosk/`)
- `apps/kiosk-pi`: Python agent on the Raspberry Pi (LEDs, dynamic NFC tag)
- `packages/protocol`: shared zod schemas and types
- `packages/start-screen`: 3D start screen (three.js + Vite), shown by the phone app at `/` once per visit. Own preview page: `pnpm dev:start` (port 5180). Every number is in `src/config.ts`.
- `scripts`: seed, ghost riders, asset build

## Rules

- pnpm workspaces, Node 22, TypeScript strict. Python 3.11 on the Pi.
- Change `packages/protocol` first when the contract changes, then the worker and clients in the same PR. Mirror kiosk event changes in `apps/kiosk-pi/protocol.md`.
- No native app, no camera, no mic, no BLE, no GPS. Location only comes from NFC taps.
- The kiosk screen is public: first names and colors only.
- Missions come from the curated deck, never generated by the LLM. The LLM only writes the one-line "why you two".
- Keep each app's README up to date with how to run it.

## Commands

```
pnpm install
pnpm db:migrate:local
pnpm dev            # worker + all three web apps
pnpm build          # build web apps and copy into apps/worker/public
pnpm run deploy
pnpm seed           # demo profiles
pnpm ghosts         # fake riders on the demo train
pnpm smoke          # end-to-end check of the happy path against a running worker
pnpm art            # re-render the phone app's artwork (apps/phone-web/public/art) with the start screen's renderer
```
